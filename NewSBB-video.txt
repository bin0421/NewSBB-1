NewSBB 제작 과정 소개 영상
==========================

[1] 제작 방식
-------------
- Hyperframe 으로 유튜브 영상 제작
- 음성 : edge TTS 여성 목소리
- 영상 길이 : 10분 이내
- 순서 : 스크립트 먼저 확정 -> 영상 제작 -> 업로드
- 업로드 후
  - 영상 설명에 저장소 링크(https://github.com/bin0421/NewSBB-1) 추가
  - README.md 에 영상 링크 추가 후 푸시


[2] 내용 구성
-------------
1. 오프닝1 - 점프 투 스프링부트 책, 강사님 저장소(실제 링크 표시 X)로부터 스프링부트 복습을 위한 서비스 제작 과정 소개
2. 오프닝2 - 복습하기와 나아가기로 나누어 진행했음을 설명
3. 진행 - 프로젝트 생성 및 기본 설정 -> 단계별 서비스 소개
4. 마무리 - 확장 가능성이 남아있음


[3] 주의사항
------------
1. 오프닝1, 오프닝2 등 내용 구성을 위한 머릿말을 화면에 띄우지 말 것
2. 커밋 단계 번호를 사용하지 말 것
3. 실제 브라우저에서 나타나는 변화(폼, 오류 화면, 버튼 등)를 보여주어 이해를 도울 것
4. 가능한 한 직전 단계와 현재 단계가 이어지도록 애니메이션을 구성할 것
5. 복습하기는 세부 단계를 그대로 사용하지 말고 흐름에 맞추어 큰 맥락에서의 변화를 보여줄 것,
   또한 모든 단계를 일일히 설명하지 말 것(스크립트로 조율)
6. 추가된 객체, 메소드, 파일, 기능 등의 역할과 그로 인한 변화를 명확하게 설명하고 화면에 보일 것
7. 수정된 내용은 이전과 이후를 비교, 어떻게 달라졌는지 설명하고 화면에 보일 것
8. 자막과 화면에 같은 내용이 나타나지 않게 하고, 화면 내 글자는 간단한 설명으로, 자세한 설명은 말로 할 것


[4] 스크립트 (확정 2026-11-13)
------------
작성 규칙
- 장면 번호와 장면 이름은 작업용이다. 화면에는 띄우지 않는다.
- [화면] : 보여줄 화면과 애니메이션. "글자 :" 는 화면에 띄울 짧은 문구(나레이션과 같은 문장을 쓰지 않는다).
- [나레이션] : edge TTS 여성 음성으로 읽을 문장. 자막으로도 나간다.
- 시간은 예상치. 한국어 TTS 약 분당 330자 기준, 나레이션 총량 약 2,900자 -> 약 9분.


장면 1. 시작 (약 40초)
[화면]
- 책 표지 일러스트(점프 투 스프링부트)와 GitHub 저장소 카드 일러스트가 나란히 등장. 저장소 주소는 표시하지 않는다.
- 두 일러스트에서 선이 뻗어 나와 가운데 빈 브라우저 창 하나로 모인다. 창 안에 "커뮤니티 사이트 A" 첫 화면이 그려진다.
- 글자 : 책 + 강의 코드 → 직접 다시 만들기
[나레이션]
스프링부트를 처음 배울 때 점프 투 스프링부트 책으로 게시판 서비스를 만들어 봤습니다.
이번에는 그 내용을 복습하려고, 강사님의 강의와 저장소 코드를 따라 게시판을 처음부터 다시 만들었습니다.
빈 프로젝트에서 시작해 글과 댓글, 회원 기능까지 갖춘 서비스가 되기까지의 과정을 소개합니다.


장면 2. 두 갈래 진행 방식 (약 35초)
[화면]
- 가운데 길 하나가 두 갈래로 갈라진다. 왼쪽 길에는 강의 코드 조각들이 순서대로 놓이고, 오른쪽 길에는 새 기능 아이콘(자물쇠, 엄지, 돋보기)이 하나씩 붙는다.
- 글자 : 왼쪽 "복습하기 — 강의 순서 그대로" / 오른쪽 "나아가기 — 없던 기능 더하기"
- 두 길이 다시 하나로 합쳐지며 완성된 서비스 화면으로 이어진다.
[나레이션]
작업은 두 갈래로 나누어 진행했습니다.
복습하기는 강의에서 코드가 바뀌는 순서를 그대로 따라가며 직접 다시 짜 보는 과정입니다.
나아가기는 강의에는 없지만 실제 서비스라면 필요할 기능을 단계마다 조금씩 더하는 과정입니다.
그래서 결과물은 강의보다 기능이 더 풍부한 게시판이 되었습니다.


장면 3. 프로젝트 뼈대 (약 45초)
[화면]
- 빈 폴더에 build.gradle.kts, BackApplication 파일이 차례로 떨어진다. 의존성 목록(Web MVC, JPA, Thymeleaf, H2)이 블록으로 쌓인다.
- 이어서 BaseEntity 블록이 생기고, 그 위에 Post 블록이 올라간다. BaseEntity 에서 id·작성일·수정일 세 칸이 Post 로 내려가는 화살표.
- 서버 실행 애니메이션 → DB 표에 "제목 1, 2, 3" 세 줄이 자동으로 채워진다.
- 글자 : 공통 필드는 부모에게 / 서버를 켜면 샘플 글 3개
[나레이션]
먼저 스프링부트 4와 자바 25로 프로젝트를 만들고 웹, JPA, 타임리프, H2 데이터베이스를 연결했습니다.
모든 엔티티가 공통으로 쓰는 번호와 작성일, 수정일은 BaseEntity라는 부모 클래스에 모았습니다.
글을 뜻하는 Post 엔티티는 이 부모를 물려받기만 하면 날짜가 자동으로 채워집니다.
그리고 서버가 켜질 때 글이 하나도 없으면 샘플 글 세 개를 넣어, 화면을 만들기 전부터 다룰 데이터가 있게 했습니다.


장면 4. 글 작성 폼과 입력값 검사 (약 95초)
[화면]
- 브라우저 주소창 /posts/write. 자바 코드 안 문자열로 만든 폼이 화면에 그려진다(제목 칸, 내용 칸, 작성 버튼).
- 작성 버튼 클릭 → 주소창에 ?title=...&content=... 가 붙는 모습(GET). 주소창이 흔들리며 빨간 줄.
- 같은 폼에서 method 가 POST 로 바뀌고 주소창이 깨끗해진다. 화면 중앙에 "1번 글이 생성되었습니다."
- 빈 제목으로 전송 → 왼쪽 "이전" 화면(문구만 덩그러니) / 오른쪽 "이후" 화면(빨간 에러 + 입력값이 남은 폼 + 커서가 틀린 칸에 깜빡임).
- 코드 비교 : 왼쪽 if 문 여섯 줄이 접히며 오른쪽 WriteForm 클래스의 @NotBlank, @Size 두 줄로 바뀐다.
- BindingResult 블록이 예외 화살표를 받아 막는다. 에러 메세지들이 순번 붙은 카드로 정렬되어 목록이 된다.
- 글자 : GET → POST / if 6줄 → 어노테이션 / 에러는 한 번에, 순서대로
[나레이션]
첫 화면은 글 작성 폼입니다. 처음에는 HTML을 자바 문자열로 직접 만들어 돌려주었습니다.
작성 버튼을 누르면 입력값이 주소 뒤에 그대로 붙는데, 이렇게 하면 새로고침만 해도 글이 또 저장될 수 있습니다.
그래서 전송 방식을 POST로 바꾸어 입력값을 요청 본문에 담았습니다.
다음은 입력값 검사입니다. 처음에는 빈 값이면 안내 문구만 보여 주었는데, 이러면 사용자가 처음부터 다시 입력해야 합니다.
그래서 에러 메세지와 함께 입력하던 값을 그대로 채운 폼을 다시 보여 주고, 문제가 있는 칸에 커서를 옮겨 주었습니다.
검사 조건이 늘어나자 if 문이 길어졌습니다. 이것을 WriteForm이라는 폼 객체로 옮기고 NotBlank, Size 같은 어노테이션으로 규칙만 선언했습니다.
검사에 실패해도 에러 페이지가 뜨지 않도록 BindingResult가 결과를 받아 두고, 모든 에러를 정해진 순서대로 보여 줍니다.


장면 5. 타임리프로 화면 분리 (약 70초)
[화면]
- 자바 파일 안의 HTML 문자열이 빠져나와 write.html 파일로 날아가 들어간다. 컨트롤러에는 "post/post/write" 한 줄만 남는다.
- 템플릿 코드 비교 : name·id·value 를 하나하나 쓴 입력칸 → th:field 한 줄. 속성들이 자동으로 펼쳐지는 애니메이션.
- 에러 목록과 포커스 스크립트가 한 덩어리로 묶여 form_errors 조각 파일이 되고, 다른 폼들에 끼워지는 모습.
- 글 작성 직후 화면 비교 : 이전(완료 문구 화면에서 새로고침 → 같은 글이 두 번) / 이후(바로 상세페이지로 이동, 새로고침해도 한 번).
- 글자 : 자바는 데이터, HTML 은 템플릿 / 에러 표시는 재사용 부품 / 작성 후 바로 이동
[나레이션]
자바 코드 안에 HTML이 섞여 있으면 화면을 고치기 어렵습니다. 그래서 타임리프 템플릿을 도입해 화면을 html 파일로 분리했습니다.
컨트롤러는 이제 어떤 화면을 보여 줄지 이름만 알려 주고, 값은 모델에 담아 넘깁니다.
th:field를 쓰면 입력칸의 이름과 아이디, 값이 자동으로 맞춰져 반복되던 코드가 크게 줄었습니다.
에러 목록과 커서를 옮기는 스크립트는 하나의 조각 파일로 떼어내, 앞으로 만들 모든 폼에서 다시 쓸 수 있게 했습니다.
또 글을 작성한 뒤에는 완료 화면 대신 리다이렉트로 바로 이동하게 했습니다. 이렇게 하면 새로고침을 해도 같은 글이 두 번 저장되지 않습니다.


장면 6. 상세, 목록, 수정 (약 45초)
[화면]
- 작성 직후 상세페이지가 열린다: 번호, 제목, 작성일, 수정일, 줄바꿈이 살아 있는 본문.
- "글 목록" 클릭 → 처음엔 JSON 텍스트가 화면 가득 → 목록 페이지로 바뀌며 제목 링크들이 줄지어 나타난다.
- "글 수정" 클릭 → 기존 제목과 내용이 채워진 수정 폼 → 수정 후 상세페이지의 수정일이 바뀌는 순간을 확대.
- 글자 : 저장 없이도 반영 — 변경 감지
[나레이션]
이제 글을 볼 수 있어야 합니다. 상세페이지에서는 본문의 줄바꿈이 그대로 보이게 했고, 목록은 처음에 데이터를 그대로 출력해 본 뒤 보기 좋은 목록 화면으로 바꾸었습니다.
수정 화면에는 기존 내용을 미리 채워 두었습니다.
수정할 때는 저장 메서드를 따로 부르지 않습니다. 트랜잭션 안에서 엔티티의 값만 바꾸면 JPA가 변화를 감지해 자동으로 반영하고, 수정일도 함께 바뀝니다.


장면 7. 댓글 (약 75초)
[화면]
- Post 블록 아래로 PostComment 블록들이 줄에 매달리듯 연결된다(하나의 글에 여러 댓글).
- 상세페이지 아래에 댓글 작성 칸이 생긴다. 한 글자만 입력하고 작성 → 브라우저 경고창 "2자 이상" → 서버로 가지 않음.
- 삭제 링크 클릭 → 확인창 → 확인 후 목록에서 댓글이 사라짐. 이전(리스트에서만 빠지고 DB 에는 남음) / 이후(DB 에서도 삭제) 비교.
- 코드 비교 : 길던 폼 클래스 → record 한 줄짜리. 수정은 PUT, 삭제는 DELETE 표지판이 요청 화살표에 붙는다.
- 모든 페이지가 같은 머리말과 꼬리말 틀(layout) 안에 끼워지는 애니메이션.
- 글자 : 글이 댓글을 관리 / 보내기 전에 먼저 검사 / 요청의 의미대로
[나레이션]
다음은 댓글입니다. 댓글은 글에 속하기 때문에 글이 댓글 목록을 가지고, 댓글 추가와 삭제도 글을 통해 하도록 만들었습니다.
글을 저장하거나 지우면 딸린 댓글도 함께 저장되고 지워집니다.
댓글 폼은 서버에 보내기 전에 자바스크립트로 먼저 검사해, 너무 짧은 댓글은 바로 알려 줍니다.
삭제는 처음에 목록에서만 빠지고 데이터베이스에는 남는 문제가 있었는데, 고아가 된 댓글을 자동으로 지우는 옵션으로 해결했습니다.
폼 클래스는 record 문법으로 짧게 줄였고, 수정은 PUT, 삭제는 DELETE처럼 요청의 의미에 맞는 방식으로 보내도록 바꾸었습니다.
마지막으로 공통 레이아웃을 만들어 모든 페이지가 같은 머리말과 꼬리말을 쓰게 했습니다.


장면 8. 스프링 시큐리티 (약 35초)
[화면]
- 사이트 앞에 성문이 내려와 모든 페이지가 로그인 화면으로 막힌다.
- 성문이 열리고 "모든 요청 허용" 깃발. 대신 폼마다 작은 열쇠(CSRF 토큰)가 붙어 전송된다. 열쇠 없는 요청은 튕겨 나감.
- 글자 : 일단 모두 통과, 대신 위조 방지 열쇠
[나레이션]
복습하기의 마지막은 스프링 시큐리티입니다. 의존성을 추가하는 순간 모든 페이지가 막히기 때문에, 우선은 모든 요청을 허용하도록 설정했습니다.
대신 다른 사이트가 몰래 요청을 보내지 못하도록 CSRF 토큰이 켜지는데, 폼에 th:action을 붙이면 이 토큰이 자동으로 들어갑니다.
여기까지가 강의를 따라 만든 내용입니다.


장면 9. 나아가기 — 글 관리 다듬기 (약 50초)
[화면]
- 상세페이지에 "글 삭제" 버튼이 나타난다 → 확인창 → 목록으로 돌아오며 글이 사라진다.
- 목록 비교 : 이전(오래된 글부터 끝없이 이어짐) / 이후(최신 글부터 10개, 아래에 페이지 번호 1 2 3).
- 주소창에 없는 글 번호 입력 → 이전(500 서버 오류 화면) / 이후("요청하신 데이터를 찾을 수 없습니다" 안내 화면).
- 목록 제목 옆에 빨간 숫자 [3] 이 붙는다.
- 글자 : 삭제 · 페이징 · 404 · 댓글 수
[나레이션]
이제부터는 나아가기입니다. 먼저 글 관리에서 비어 있던 부분을 채웠습니다.
강의에는 글 삭제가 없어서 삭제 기능을 더했고, 목록은 최신 글부터 열 개씩 페이지로 나누었습니다.
없는 글에 접근하면 서버 오류가 나던 것을, 전역 예외 처리로 찾을 수 없다는 안내 화면으로 바꾸었습니다.
목록에는 댓글 수를 표시하고, 이때 댓글을 한꺼번에 불러오도록 설정해 쿼리가 글 수만큼 늘어나는 문제도 막았습니다.


장면 10. 나아가기 — 회원과 권한 (약 65초)
[화면]
- 헤더에 "로그인 / 회원가입" 메뉴. 회원가입 폼에서 비밀번호 확인을 다르게 입력 → 빨간 에러, 해당 칸에 커서.
- 가입 → 로그인 → 헤더가 "user1님 / 로그아웃" 으로 바뀌는 순간을 확대.
- DB 표의 비밀번호 칸 : 이전(입력한 그대로) 대신 알아볼 수 없는 긴 문자열이 들어가는 모습.
- 글 목록과 상세에 작성자 이름이 붙는다. 로그아웃 상태로 글쓰기 클릭 → 로그인 화면으로 이동.
- user2 로 다른 사람 글 상세 → 수정·삭제 버튼이 보이지 않는다. 주소를 직접 입력 → "권한이 없습니다" 화면.
- 글자 : 비밀번호는 암호화 / 쓰려면 로그인 / 내 글만 고칠 수 있게
[나레이션]
다음은 회원 기능입니다. 회원가입에서는 비밀번호를 그대로 저장하지 않고 BCrypt로 암호화해 저장합니다.
비밀번호 확인이나 아이디 중복처럼 어노테이션으로 표현하기 어려운 검사도 같은 에러 형식으로 보여 주어, 앞에서 만든 에러 조각을 그대로 썼습니다.
로그인과 로그아웃은 시큐리티에 맡기고, 헤더 메뉴는 로그인 상태에 따라 바뀌게 했습니다.
이제 글과 댓글에 작성자를 저장하고, 로그인하지 않으면 글을 쓸 수 없게 했습니다.
또 작성자 본인만 수정하고 삭제할 수 있도록 서버에서 확인하고, 화면에서도 본인에게만 버튼을 보여 줍니다.


장면 11. 나아가기 — 더 쓰기 좋은 게시판 (약 65초)
[화면]
- 상세페이지 "추천" 버튼 클릭 → 숫자 0 → 1, 버튼 글자가 "추천 취소" 로 바뀜. 댓글에도 같은 버튼.
- 목록 위 검색창에 "스프링" 입력 → 결과만 남는다. "최신순 | 추천순" 전환 → 추천 많은 글이 위로 올라가는 정렬 애니메이션.
- 글 본문 비교 : 이전(**굵게**, - 목록 기호가 글자 그대로) / 이후(굵은 글씨와 목록으로 렌더링). <script> 를 넣어도 글자로만 보이는 모습.
- 긴 댓글 목록에서 댓글 작성 → 페이지 맨 위가 아니라 방금 쓴 댓글 위치로 스크롤.
- 상세 상단 "조회수" 숫자가 새로고침마다 올라간다.
- 글자 : 추천 · 검색 · 정렬 · 마크다운 · 바로 그 자리로 · 조회수
[나레이션]
마지막으로 게시판을 더 쓰기 좋게 다듬었습니다.
글과 댓글에 추천 기능을 넣었는데, 한 번 더 누르면 추천이 취소됩니다.
목록에는 제목과 내용, 작성자로 찾는 검색과 추천순 정렬을 더했고, 페이지를 넘겨도 검색어와 정렬이 유지됩니다.
본문과 댓글은 마크다운으로 꾸밀 수 있게 하되, 직접 입력한 HTML은 글자로만 보이게 해서 보안 문제를 막았습니다.
댓글을 쓰거나 고친 뒤에는 그 댓글 위치로 바로 이동하고, 글마다 조회수도 보여 줍니다.


장면 12. 마무리 (약 30초)
[화면]
- 완성된 서비스의 화면들(목록, 상세, 로그인, 검색 결과)이 카드처럼 펼쳐졌다가 하나로 모인다.
- 카드 뒤로 아직 비어 있는 카드 몇 장이 희미하게 보인다(물음표 아이콘).
- 글자 : 아직 남은 빈칸들
- 마지막에 저장소 이름 "NewSBB" 만 표시(링크는 영상 설명란에).
[나레이션]
이렇게 강의의 흐름을 따라 복습하고, 그 위에 필요한 기능을 하나씩 더해 게시판을 완성했습니다.
하지만 아직 끝은 아닙니다. 비밀번호 찾기나 소셜 로그인, 조회수 중복 방지처럼 더 나아갈 수 있는 부분이 남아 있습니다.
전체 코드와 단계별 기록은 영상 설명란의 저장소에서 확인하실 수 있습니다. 시청해 주셔서 감사합니다.
